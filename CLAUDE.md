# CLAUDE.md

Kodi service add-on `service.marantz.remote` ("Marantz AVR Remote"): a phone/browser remote for a Marantz AV7705. See README.md for what it does from a user's point of view.

## Environment quirks (read first)

- **The add-on folder is on an SSHFS mount** of the LibreELEC Kodi 21 box (drive letter currently `Y:`, previously `W:`; `//sshfs/root@10.0.10.250`, i.e. `/storage`).
  - The Write tool fails there (EPERM on mkdir). Write or edit copies in the scratchpad, then `cp` them over with Bash. Before copying, check the scratch copy still matches the committed file (`git show HEAD:<path>`), because the user also edits in VS Code.
  - The drive sometimes drops out (Kodi box rebooting). Shell commands then fail until it's back.
- **Git:** the repo's database is on local disk at `C:\Users\joshc\repos\service.autoexec.git`; the add-on folder has only a `.git` pointer file, because `git init` fails over SSHFS. The global git config has a `safe.directory` entry for the SSHFS path. Remote: private GitHub repo `sissylettice/service.autoexec`, branch `main`. Line endings are forced to LF (`.gitattributes`, `core.autocrlf false`) because the files run on Linux.
- **No SSH access for Claude** (password auth only). The user restarts Kodi themselves: `ssh root@10.0.10.250 systemctl restart kodi`.
- Commit or push only when the user asks; they often commit from VS Code themselves.

## How it works

- `service.py`:
  - `Avr` holds one TCP connection to the AVR on port 23. A reader thread parses `\r`-terminated lines into the `state` dict, and changes are broadcast to all pages as `{"state": {...}}`.
  - Reconnects with backoff. A 60 s keepalive (`ZM?`) catches dead connections, and a connection silent for 75 s is dropped and reopened.
  - Commands are spaced at least 50 ms apart (Marantz requirement).
  - On connect it sends `STATUS_QUERIES`.
- **Page ↔ service** messages are JSON over WebSocket:
  - The page sends `{"cmd": ...}`. `handle_command` validates every value (whitelists and regexes) before building an AVR command; never pass page text straight to the AVR.
  - Errors go back as `{"error": "..."}` to that client only.
  - New clients get a snapshot: `{"avr", "config", "state"}`.
- **Settings** are read through `get_setting()`, which creates a fresh `xbmcaddon.Addon` each time so changed values are picked up.
  - `ServiceMonitor.onSettingsChanged` → `apply_settings()`: AVR address changes apply live; port changes need a Kodi restart.
  - The page's address card saves through `set_setting('avr_host')`.
- `/config.js` is generated by the HTTP handler; it tells the page the WebSocket port.
- **Volume:** state stores dB, where `MV` level 80 = 0 dB. The page shows absolute (level) or relative (dB) per the `volume_display` setting. `max_volume` is absolute; `volume_cap()` converts it to dB and also respects the AVR's `MVMAX`.
- The page ignores AVR echoes for a slider for 700 ms after the user touches it, then snaps to the AVR's value.

## AVR protocol facts (verified on this AV7705 via the Kodi log)

No AV7705 protocol document could be downloaded (Marantz's site fails TLS from this PC). **The Kodi log is the source of truth**: the service logs every line as `[service.marantz.remote] FROM AVR < ...` / `TO AVR > ...` in `Y:\.kodi\temp\kodi.log` (previous run: `kodi.old.log`). Check it before assuming any command format, and ask the user to make a change on the AVR while the service runs to see what it reports.

- **Levels:** `MV`, `CV` and `PSLFE` use 2-digit values, or 3 digits for half-dB steps (`MV555` = 55.5, `CVSR 555`). `MV80` = 0 dB and `CVx 50` = 0 dB; `CV?` lists channels and ends with `CVEND`.
- **Power:** `ZMON` / `ZMOFF` for the main zone.
- **Display:** `DIM BRI|DIM|DAR|OFF` and `DIM ?`.
- **Dynamic Compression is `PSDRC`.** `PSDCO` gets no answer. `PSDRC HI` (not `HIGH`) is unverified.
- **Sound mode:** `MS` replies are the decoder actually in use, e.g. `MSDOLBY AUDIO-DSUR`, `MSNEURAL:X`, `MSMULTI CH IN`, `MSSTEREO`, `MSPURE DIRECT`. `SSSMG MOV|MUS|GAM|PUR` is the button group last used.
- **Inputs:** `SSFUN ?` returns custom names (`SSFUNSAT/CBL AppleTV` … `SSFUN END`). `SSSOD ?` returns which inputs are used (`SSSODDVD DEL` … `SSSOD END`).
- **Subwoofer and LFE:** only reported or adjustable in multichannel modes.
- **Porthole/illumination:** the AVR sends nothing when it changes; treat it as not network-controllable.
- **Model:** the AVR identifies as `VIALLAV7705 U`.

## Testing

No test suite in the repo. Before installing a change to `service.py`, run it outside Kodi against a fake AVR: import `service`, set `avr.port`, `BIND_HOST` and `_test_settings`, then start `main()` in a thread.
- A small TCP server on `127.0.0.1` can stand in for the AVR, and a second loopback address (`127.0.0.2`) for an address-change test.
- Check that `handle_command` builds the right AVR commands and rejects bad input, and that it reconnects after the fake AVR drops the connection.
- Validate `addon.xml` and `settings.xml` with `xml.etree`, and check every settings label id exists in `strings.po`.

Node isn't installed, so the page's JavaScript can't be syntax-checked here. Change it carefully and ask the user to reload and check on their phone.

After installing: changes to `service.py` need a Kodi restart; page-only changes just need a reload (the server sends `Cache-Control: no-cache`). Then check the Kodi log for errors.

## Style

- **Python:** Kodi 19+ (Python 3.8-compatible; the box runs Kodi 21). Stdlib only, apart from the bundled `websocket_server`. Log with `log()`, not print.
- **Page:** plain JS (ES5-style `var`, no build step, no jQuery). Inputs need font-size ≥ 16px so iOS doesn't zoom. Buttons use `touch-action: manipulation` to stop double-tap zoom.
- Bump `version` and add a `news` entry in `addon.xml` for user-visible changes.
